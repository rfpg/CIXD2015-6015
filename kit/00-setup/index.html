Set up: your repo and your live page

In Figma you shared a prototype link. On the web the equivalent is a repository with GitHub Pages switched on: the files are the design, the URL is the share link. This page gets you from nothing to a live address in about fifteen minutes.

Publish once

  1. Make a GitHub account at github.com, with any email. The free plan is enough; it publishes public repos, and a cover story is public anyway.
  2. Make a repository of your own. The + menu at the top right of GitHub, then New repository. Name it in lowercase with hyphens, short, like cover-story. Public. Create repository. It's empty; that's right.
  3. Put the starter in it. The Cover Story starter lives in the course repo (here it is, live). On the course repo page: the green Code button, Download ZIP. Unzip, open the starter folder. Back in your new repo: uploading an existing file (or Add file, Upload files), drag in everything inside starter, the css, js and img folders included, then Commit changes.
  4. Switch on Pages. In your new repo: Settings, then Pages in the left menu. Under Build and deployment, set Source to Deploy from a branch, Branch to main and / (root), then Save. Wait a minute and refresh the page; it now says Your site is live at your address. Bookmark that address; it's the one you'll put on the cover story in December.

Edit, every time

  1. Keep the folder on your computer. The starter folder you unzipped is your working copy; rename it to match your repo (cover-story). Lost it? Your repo's green Code button, Download ZIP, gets it back.
  2. Edit and preview. Install VS Code (free). File, Open Folder, pick your folder. Then double-click index.html so it also opens in your browser. Change something, save (Ctrl/⌘ + S), refresh the browser. That's the whole loop; you'll do it a hundred times on Wednesday.
  3. Publish. On your repo page: Add file, Upload files. Drag in the files you changed. Drag whole folders (css, img) so files land where the page expects them. Then Commit changes. Within a minute the live page shows the new version; if it looks old, hard-refresh with Shift + reload.

Three rules that save an afternoon

RuleBecause
Paths are relative: css/tokens.css, never /css/tokens.cssYour site lives in a subfolder of github.io. A leading slash points at the wrong place and the page loads unstyled.
Filenames are lowercase, no spaces, exact extensionOnline, hero.jpg and Hero.JPG are two different files. It worked on your laptop; it breaks on the server.
index.html keeps that exact nameIt's the file the address opens. Rename it and the URL shows a 404.

If the live page looks stale after a minute: hard-refresh. If it's still stale, open the repo's Actions tab; a run called pages build and deployment should be green. Yellow means wait; red means a filename or path problem, and the log says which.

Before you leave Sprint 0

  • Your Pages address opens on your phone, not just your laptop.
  • The masthead says the magazine you chose.
  • The headline is yours. The six words are exactly six.
  • The colors come from css/tokens.css and they're your Assignment 1 palette. (Module 01.)
  • The theme toggle works on the live page.
