Tokens: Figma variables, in CSS

A variable in Figma is a named value that things point at. In CSS the same thing is a custom property. Components never hold a raw color; they hold a name, and the name is what changes when the mode changes.

The same idea, two names

In FigmaIn CSSNote
A color variable, blue/500--blue-500: #2a3de8; inside :root { }A primitive: named by what it is
An alias, color/accent → blue/500--color-accent: var(--blue-500);A semantic token: named by what it's for
A number variable, space/2 = 16--space-2: 1rem;Spacing, radius and type sizes are tokens too
Apply a variable to a fillbackground: var(--color-accent);The component references the name
A mode: Light / Dark[data-theme="dark"] { --color-bg: var(--ink-900); }Redefine semantic tokens only; primitives stay
Set a frame's mode<html data-theme="dark">Modes are set on an element and cascade to everything inside it

The code behind it

This is the whole system for the phone. In your starter the same block lives on :root in css/tokens.css, so it reaches the entire page.

/* 1. Primitives: raw values, named by what they are */
:root {
  --ink-900: #14161a;   --ink-800: #23262d;
  --paper-50: #f6f5f1;  --paper-100: #ebe9e2;
  --blue-500: #2a3de8;  --blue-300: #8d98ff;
  --gray-500: #6e7079;  --gray-300: #a3a6b0;

  /* 2. Semantic tokens: named by what they're for. Components use only these. */
  --color-bg: var(--paper-50);
  --color-surface: var(--paper-100);
  --color-text: var(--ink-900);
  --color-muted: var(--gray-500);
  --color-accent: var(--blue-500);
  --color-on-accent: var(--paper-50);
  --hand-flow: row;
}

/* 3. Modes: redefine semantic tokens only. Primitives never change. */
[data-theme="dark"] {
  --color-bg: var(--ink-900);     --color-surface: var(--ink-800);
  --color-text: var(--paper-50);  --color-muted: var(--gray-300);
  --color-accent: var(--blue-300); --color-on-accent: var(--ink-900);
}
[data-hand="left"] { --hand-flow: row-reverse; }

/* 4. Components point at names, never at values. */
.bar  { display: flex; flex-direction: var(--hand-flow); justify-content: space-between; }
.tabs { display: flex; flex-direction: var(--hand-flow); }
.action { background: var(--color-accent); color: var(--color-on-accent); }

And the JavaScript that drives a toggle is one line that matters: set the attribute. The browser does the rest.

// Which element carries the mode? Here the phone; in your starter, <html>.
const phone = document.querySelector(".phone");

// e.g. phone.dataset.hand = "left"  →  <div class="phone" data-hand="left">
phone.dataset.hand = "left";

Why a component never holds a raw color

Because the mode switch would miss it. A button painted #2a3de8 stays blue in the dark, where the rest of the screen has moved to the light blue that reads on black. A button painted var(--color-accent) moves with everything else. Same in Figma: a detached fill doesn't follow the mode. The rule has one job: make the system change in one place.

The name is the design decision. --blue-500 says what a color is. --color-accent says what it's for. Your cover needs a few of the second kind: background, surface, text, muted, accent, and whatever your product adds (a --color-quote, a --color-danger). If you can't name what a color is for, you probably don't need it yet.

Try it in your starter

  1. Open css/tokens.css. Replace the primitives with your Assignment 1 palette, keeping the naming pattern (--name-weight). Save, refresh. The cover repaints and you changed nothing else.
  2. Add one semantic token the cover needs, like --color-quote, and point .quote in css/base.css at it instead of --color-surface.
  3. Make the dark mode yours: in the [data-theme="dark"] block, choose which of your primitives each semantic token points at in the dark. Press the toggle; check the quotes still read.
  4. Stretch: add --hand-flow: row; to your tokens, give .masthead a flex-direction: var(--hand-flow), and a data-hand="left" on <html> moves the toggle to the other side.
